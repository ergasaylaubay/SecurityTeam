## Ұсынылған архитектуралық шешімдер
Бұл тармақтар тапсырмадағы қосымша міндетті талаптар емес, команданың бекітуіне ұсыныс.
Java 17+ — барлық модульдің негізі; нақты JDK/Spring Boot нұсқаларын код басталғанда біріздендіру.
Spring Boot — REST API және бизнес логика; Spring Security — session, рөл және endpoint қорғанысы; JavaFX — desktop интерфейс; JCA — стандартты криптография.
PostgreSQL — ортақ негізгі база; H2 — жеңіл локалды тәжірибе. PostgreSQL интеграциялық тесттерін H2 тесттерімен алмастырмау.
HTTPS REST — кіру, чат, хабар жіберу және тарих. WSS/STOMP — жаңа хабар бар екені туралы жеке хабарлама. Polling қарапайым, бірақ бос сұрау көбейеді; WSS біршама күрделі, алайда real-time көрсетуге ыңғайлы. Бұл — жобалық таңдау.
Session authentication — осы MVP үшін таңдау; JWT осы тапсырмада міндетті емес. JavaFX HTTP және WSS бір session-ды қолданады; өзгерту сұрауларында CSRF қорғанысы сақталады.

## Рөлдер және шекара
USER: өз чаттарын ашу, хабар жіберу/оқу; топты құру. Топ OWNER-і мүшелерді басқарады.
ADMIN: аккаунтты белсендіру/бұғаттау, рөл тағайындау, аудит қарау. ADMIN рөлі бөтен чатқа автоматты қолжетімділік бермейді.
Тіркелу PENDING аккаунтын жасайды; ADMIN белсендіреді. Бұл корпоративтік қолжетімділікке ұсынылған саясат.
Осы апта нәтижесі: research + UML. Қоңырау, файл жіберу, мобильді клиент — бастапқы көлемге кірмейді. Негізгі жеке/топтық чат, қауіпсіздік, админ, аудит финалдық MVP ішінде қалады.

## Деректер және API жобасы
User, Chat, ChatMember, Message, AuditEvent. Құпиясөз тек passwordHash; хабар базада ciphertext түрінде.
POST /auth/register; POST /auth/login; POST /auth/logout.
POST /chats; GET /chats; POST/DELETE /chats/{id}/members.
POST /messages; GET /chats/{id}/messages; GET /messages/{id}.
PATCH /admin/users/{id}; GET /admin/audit.
WSS /ws және /user/queue/notifications: тек өз хабарламалары; клиентке еркін broker topic-ке жариялауға рұқсат берілмейді.

## Тексерілетін қабылдау шарттары
Кірусіз чат API қолжетімсіз. USER админ API-ге кіре алмайды. Чат мүшесі емес адам history/send әрекетін орындай алмайды. Бұғатталған аккаунттың session/socket-і тоқтайды. Жеке чатта 2 мүше; топта кемінде 2 мүше және 1 OWNER. Үш клиентпен топтық чат сценарийі көрсетіледі.
Файлдағы финалдық талаптар: main/develop/feature/*, main-ге PR және кемінде 1 review, README/LICENSE/.gitignore, кемінде 20 JUnit тесті, GitHub Actions, v1.0 және 10–15 минут қорғау. Бұлар түгел осы аптада аяқталуға тиіс деп қарастырылмайды.
