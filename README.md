# Қауіпсіз корпоративтік мессенджер

Java 17+, Spring Boot, JavaFX және PostgreSQL негізіндегі топтық оқу жобасы.

Команда: Ерқанат — криптография; Нұрбек — сервер; Ерасыл — JavaFX; Нұрсұлтан — аутентификация және рұқсаттар.

## Git тәртібі

`main` — тексерілген нұсқа, `develop` — біріктіру, `feature/*` — жаңа жұмыс.
Код PR арқылы беріледі. `main` тармағына біріктіру алдында кемінде бір командалас тексереді.
Әр студент өзінің нақты үлесін commit/PR арқылы көрсетеді; дайын кодты түсініп, тестін орындауы керек.
Парольдер мен жеке кілттер Git-ке қосылмайды.

## Қазіргі күйі

Бұл алғашқы commit тек жоба негізі мен Research/UML материалдарын қамтиды.
Осы аптаның коды бөлек feature тармағында әзірленеді.
SecurityTeam — Қауіпсіз корпоративтік мессенджер

SecurityTeam — корпоративтік ортада пайдаланушылардың жеке хабарламаларын қауіпсіз жеткізуге арналған Java негізіндегі оқу жобасы. Клиент JavaFX, сервер Spring Boot арқылы жасалған; тасымалдау кезінде TLS, хабарлама payload-ында RSA-OAEP + AES-GCM қолданылады. Бұл толық end-to-end encryption (E2EE) емес: сервер хабарламаны өңдеу барысында мәтінді аша алады.

Жобаның мақсаты және зерттеу нысаны

Зерттеу нысаны — қызметкерлері ішкі ақпарат алмасатын үлгілік корпоративтік ұйым (нақты компания зерттелгені құжаттармен расталмаған). Мақсат — тіркелген қызметкерлерге жеке чат ашу, хабарлама жіберу және тарихты қарау мүмкіндігін беріп, бөтен пайдаланушылардың чатқа қолжетімділігін шектеу. Толық талдау: docs/research.md.

Технологиялар және модульдер

• Java 17+, Maven — құрастыру және тәуелділіктер.
• Spring Boot 3.5.7, Spring Security, Spring JDBC — REST API, сессиялық аутентификация және дерекқор.
• JavaFX 21.0.9 — desktop интерфейс.
• PostgreSQL — негізгі дерекқор; H2 — жергілікті demo режимі.
• JCA — RSA-OAEP, AES-256-GCM; BCrypt — пароль хэші.
• JUnit / Spring Boot Test — криптографиялық және интеграциялық тесттер.

Кодта іске асырылған функциялар

• Тіркелу, login/logout және сессиялық аутентификация; парольдер BCrypt арқылы хэштеледі.
• Жеке чат ашу және өз чаттарының тізімін алу.
• Чат мүшелігін тексеріп, шифрланған хабарлама жіберу; хабарламалар тарихын оқу.
• RSA-OAEP арқылы AES кілтін орау, AES-GCM арқылы хабарламаны қорғау және серверде шифрланған сақтау.
• HTTPS конфигурациясы, CSRF қорғанысы, ADMIN маршрутына рөлдік шектеу.
• Қабылданған хабарламалар мен тіркелуді аудит кестесіне жазу.
• DemoDataReader.java арқылы CSV файлдарының құрылымын тексеріп, жолдарын санау (негізгі мессенджердің дерекқор импорты емес).

Әзірге толық іске асырылмаған: топтық чат, WebSocket real-time хабарламалары, толық әкімші панелі, аудитті қарау API, толық рөл/аккаунт басқаруы. research-1.md және UML файлдарындағы кей сценарийлер жоспарланған архитектураны сипаттайды, сондықтан оларды дайын функция ретінде қабылдамаңыз.

Жүйе қалай жұмыс істейді?

1. Пайдаланушы JavaFX клиентінде тіркеледі немесе кіреді.
2. Клиент HTTPS арқылы Spring Boot API-мен байланысады.
3. Сервер сессияны және чатқа мүшелікті тексереді.
4. Клиент хабарлама мәтінін AES-GCM арқылы шифрлап, AES кілтін сервердің RSA public key-імен орайды.
5. Сервер қорғалған тасымалдау пакетін ашады, дерекқорға сақтау үшін бөлек AES-GCM шифрлауын қолданады.
6. Рұқсаты бар чат мүшесі тарихты сұрағанда сервер мәтінді ашып, HTTPS арқылы қайтарады.

Іске қосу (Windows)

Алғышарттар: Java 17 немесе жаңарақ JDK, Maven (java -version, mvn -version), Windows PowerShell. run.bat жергілікті кілт қоймасын дайындауға арналған keytool құралын да пайдаланады.

run.bat

Скрипт жергілікті key store паролін сұрайды (кемінде 12 таңба), қажет болса scripts/setup-local.ps1 орындайды, mvn clean package арқылы жинайды, H2 demo режиміндегі серверді және JavaFX клиентін іске қосуға тырысады. Парольді GitHub-қа жүктемеңіз. Бұл нұсқаулық кодтағы скриптке негізделген; толық графикалық іске қосу осы ортада расталмаған.

Қолмен жинау:

mvn clean package
mvn test

Негізгі PostgreSQL режимінде дерекқор мен DB_URL, DB_USER, DB_PASSWORD, MESSENGER_KEYSTORE_PASSWORD және TLS key store конфигурациясы қажет. Demo режимінде application-demo.properties арқылы H2 қолданылады. Сервердің HTTPS порты — 8443; тексеру endpoint-і: https://localhost:8443/health (жергілікті сертификатқа сенім орнату қажет болуы мүмкін).
